# Protecting the hosts

## This is the most dangerous surface in the Calico API

A HostEndpoint tells Calico to apply policy to a node's own network interface. The moment one
exists and no policy allows your traffic, **you can lock yourself out of the node — including SSH
and the kubelet.** Calico publishes no reversal operation and no reversal window
(`conventions/calico-conventions.yml`), and `deleteHostEndpoint` is your only exit, which you may
no longer be able to reach.

Sequence matters more here than anywhere else in this API:

1. **Write the allow policies first.** `createGlobalNetworkPolicy` for management access — SSH,
   kubelet, the API server, your monitoring — selecting the host endpoints by label.
2. **Rehearse.** Author them as StagedGlobalNetworkPolicy, or send with `--dry-run=server`.
3. **Then** `createHostEndpoint`, on one node, and verify you still have access before touching
   the rest.

## HostEndpoint

`createHostEndpoint`:

- `spec.node` — the Kubernetes node name. Required in practice.
- `spec.interfaceName` — the interface to protect. The special value `*` means all interfaces, which
  is the setting most likely to lock you out.
- `spec.expectedIPs` — the addresses Calico should treat as belonging to this endpoint.
- `spec.profiles[]` — a list of **Profile names**. One of only two real by-name references in the
  whole API. `listProfile` / `readProfile` first: profiles are generated by Calico from Kubernetes
  namespaces and service accounts, they are read-only, and naming one that does not exist gets you
  nothing useful.
- `spec.ports[]` — named ports, `{name, port, protocol}`, referenceable from policy rules.

**There is no `replaceHostEndpoint` in this contract.** The API declares list, create, read and
delete only. To change one you delete and re-create — which means a window in which the node is
either unprotected or unreachable, depending on ordering. Plan for it, or make the change with
`calicoctl apply` against the CRD instead.

## GlobalNetworkPolicy

Same shape as a namespaced NetworkPolicy, cluster-scoped, and it can additionally select namespaces:

- `spec.selector` — which endpoints, host and workload, this applies to.
- `spec.namespaceSelector` — which namespaces are in scope.
- `spec.order` and `spec.tier` — evaluation order. `tier` is a by-name reference to a Tier object;
  if the named Tier does not exist the policy is not admitted.
- `spec.types: [Ingress, Egress]` and `spec.ingress[]` / `spec.egress[]` with `action` one of
  `Allow`, `Deny`, `Log`, `Pass`.

`Pass` is the one worth understanding before you use it: it stops evaluating the current tier and
hands the decision to the next one. It is not `Allow`.

## Changing a global policy

`replaceGlobalNetworkPolicy` is a full replacement. `readGlobalNetworkPolicy`, keep
`metadata.resourceVersion`, modify, send it back with that version. On `409 Conflict`, re-read and
re-apply your change to the fresh copy. Never blank `resourceVersion`.

Because these are cluster-scoped, a bad `spec.selector` here is a cluster-wide event, not a
namespace-wide one. Read what `listGlobalNetworkPolicy` returns before adding to it.

## Errors

The Kubernetes `metav1.Status` envelope — branch on `reason`, not `message`. 401 Unauthorized and
404 NotFound and 409 Conflict are declared. 403 Forbidden (RBAC) and 422 Invalid (validation) are
**not declared in the spec** but occur constantly; see `errors/calico-problem-types.yml`.

## Cleaning up

`deleteHostEndpoint` removes host protection immediately — the node goes from firewalled to open in
one call. `deleteGlobalNetworkPolicy` removes cluster-wide enforcement the same way. Neither can be
undone, and neither warns you. If the policy was the thing denying traffic, deleting it opens the
cluster silently.
